# 2.apixspb.ru — Apixspb Machine Monitor (новая система)

Новая система обслуживания игровых аппаратов, построенная по нормативному комплекту
`Apixspb_FINAL_Source_of_Truth_v1`. Развёрнута отдельным стеком контейнеров и не связана
с сайтом `1.apixspb.ru` (старый PHP/MariaDB) ни кодом, ни базой.

Принятые при реализации решения — в [DECISIONS.md](DECISIONS.md).

## Состав

| Сервис      | Контейнер   | Что делает                                              |
| ----------- | ----------- | ------------------------------------------------------- |
| `db`        | `site2-db`  | PostgreSQL 16, том `2_db-data`                          |
| `api`       | `site2-api` | Node 22 + Fastify, миграции при старте, порт 3000        |
| `web`       | `site2-web` | nginx: раздаёт PWA и проксирует `/api` в `api`           |

## Эксплуатация

Прод перенесён 16.09.2026 с локальной машины на отдельный сервер (адрес и доступ — у владельца,
не в этом репозитории) — см. DECISION-077. Этот каталог (`/home/s/Work/sites/2`) на локальной
машине остаётся местом разработки; изменения на прод выкатываются вручную:

```bash
# с локальной машины — скопировать код на сервер (SERVER — адрес прод-сервера)
# docker-compose.yml НЕ синхронизируется — см. предупреждение ниже
rsync -az --exclude 'node_modules/' --exclude '.git/' --exclude 'dist/' --exclude 'backups/' \
  --exclude '.import-fedor-images/' --exclude '*.tsbuildinfo' --exclude '.env' \
  --exclude 'docker-compose.yml' --exclude 'docker-compose.override.yml' \
  ./ root@$SERVER:/opt/sites/2/

# на сервере — пересобрать и перезапустить (обычно нужен только web или api, а не всё сразу)
ssh root@$SERVER
cd /opt/sites/2
docker compose build web   # или api — какой слой менялся
docker compose up -d web
docker compose ps                 # состояние
docker compose logs -f api        # логи API
docker compose restart api        # перезапуск
```

**Важно: `docker-compose.yml` на сервере — не копия этого файла в репозитории, а отдельная,
осознанно другая версия** (другой Traefik-роутер на `Host(`2.apixspb.ru`)` вместо общего для
нескольких сайтов, том БД называется `db-data`, без `TEST_SERVER_PUBLIC_IP`/публикации порта —
см. DECISION-077 и DECISION-078). Локальный `docker-compose.yml` в этом репозитории, наоборот,
настроен под локальный тестовый стенд (том `test-db-data`, роутер `site2test` на
`${TEST_SERVER_PUBLIC_IP}`, порт `8091`). Затирать один другим через `rsync ./` **нельзя** — 16 и
17.09.2026 это уже приводило к тому, что боевой `site2-db` на несколько минут переключался на
пустой тестовый том. Если `docker-compose.yml` на сервере всё же нужно поменять — делать это
вручную, глядя на разницу, а не синхронизацией всего каталога.

Внешний доступ на новом сервере — через отдельный Traefik в `/opt/traefik-root/` (не тот общий
Traefik из `/home/s/Work/docker-compose.yml`, что остался на локальной машине для `site1`/`site3`).
Сертификат — Let's Encrypt по HTTP-01 только на `2.apixspb.ru` (не wildcard: reg.ru-креды для
DNS-01 на новый сервер осознанно не переносились, см. DECISION-077).

Секреты (пароль БД, JWT-ключ, первый администратор) лежат в `.env` рядом с compose-файлом и на
локальной машине, и на сервере — не в git, не попадают в образы.

### База данных

```bash
docker exec -it site2-db psql -U apixspb -d apixspb
docker exec site2-db pg_dump -U apixspb apixspb | gzip > backup-$(date +%F).sql.gz
```

Миграции применяются автоматически при старте `api` и записываются в `schema_migrations`.
Новая миграция — это просто новый `.sql` файл в `api/src/migrations/` с большим номером.

### Полный сброс данных

```bash
docker compose down -v && docker compose up -d
```

Учётная запись администратора создаётся заново из `.env` только если таблица сотрудников пуста.

## Разработка

```bash
cd api && npm install && npm run dev     # API на :3000
cd web && npm install && npm run dev     # PWA на :5173 с проксированием /api
```

Тесты API идут против настоящего PostgreSQL:

```bash
docker run -d --name apixspb2-test-db -e POSTGRES_PASSWORD=test -e POSTGRES_DB=apixspb_test \
  -p 55432:5432 postgres:16-alpine
cd api && npx tsx --test --test-concurrency=1 tests/*.test.ts
```

Тесты пересоздают схему из тех же миграций, что и продакшен, поэтому проверяют реальные
ограничения БД, а не их упрощённую копию.

## Что реализовано

- Location → Placement → Machine с историей: локация не удаляется, номер аппарата не
  переиспользуется, у аппарата не может быть двух активных установок.
- Цепочка счётчиков с коэффициентом деления, пересчёт всей истории аппарата одним SQL-выражением.
- Обязательное фото счётчика, идемпотентная оффлайн-синхронизация по `local_id`.
- Интервальная история терминалов и историческое сопоставление cashless на момент транзакции.
- RBAC (администратор / техник / руководитель) с серверной проверкой на каждом endpoint.
- Audit всех бизнес-мутаций в той же транзакции, что и сама мутация.
- Единый расчётный слой для отчётов, сводки и выгрузки CSV.
- PWA: установка на телефон, работа без сети, очередь обслуживаний, справочный расчёт.

## Что осознанно не сделано

- Живая интеграция с платёжным провайдером (нет учётных данных) — есть только приёмный endpoint
  и matcher.
- UI закрытия локации и замены аппарата — операции доступны через API.
- Конкурентные (нагрузочные) тесты — см. границу верификации в `DECISIONS.md`.
