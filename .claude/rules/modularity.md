# Правила модульности и безопасных изменений

Постоянный раздел. Действует для всех задач в этом репозитории, если владелец явно
не сказал иного для конкретной задачи.

## Правила

1. Перед любым изменением, которое затрагивает больше одного модуля (client / server /
   shared) или схему БД — сначала опиши план: какие файлы будешь менять и почему, без
   написания кода. Дождись подтверждения.

2. Изменения делай в границах одного слоя за раз, не смешивая их в одном шаге:
   - `packages/shared` (типы, схемы),
   - БД / миграции,
   - API-роуты,
   - клиент.

3. Не трогай код, не относящийся к текущей задаче, даже если он выглядит неидеальным.
   Отдельная идея — отдельный запрос в будущем.

4. Новую логику выделяй в отдельные функции/модули с понятным интерфейсом входа/выхода,
   а не встраивай в существующие большие функции.

5. Если изменение может повлиять на уже работающий функционал — явно назови это в ответе:
   что именно может задеть.

6. После изменения прогоняй существующие тесты/сборку. Если тестов на затронутую часть
   нет — сообщи об этом явно и предложи добавить.

7. Делай отдельный git-коммит на каждый логически завершённый шаг с понятным сообщением,
   а не один большой коммит в конце задачи.

8. Если задача требует менять контракт (API, схему БД, формат данных) — сначала покажи,
   что именно меняется в контракте, и жди подтверждения, прежде чем менять реализацию.

9. Если в процессе работы понимаешь, что нужно сделать что-то за пределами описанной
   задачи — остановись и спроси, не делай это самостоятельно.

## Как слои из правила 2 называются в этом репозитории

Отдельного пакета `packages/shared` здесь нет: репозиторий состоит из `api/` и `web/`,
общие типы продублированы на обеих сторонах. Порядок слоёв при этом тот же:

| Слой из правила 2   | Где лежит в этом репозитории                                  |
| ------------------- | ------------------------------------------------------------- |
| shared (типы/схемы) | интерфейсы в `api/src/commands/*.ts`, `api/src/domain/*.ts` и их зеркала в `web/src/` |
| БД / миграции       | `api/src/migrations/NNN_*.sql`                                 |
| API-роуты           | `api/src/routes/*.ts` и `api/src/commands/*.ts`                |
| клиент              | `web/src/`                                                     |

Команды для правила 6:

```bash
cd api && npx tsc -p tsconfig.json --noEmit     # типы API
cd web && npx tsc -b                            # типы клиента
docker start apixspb2-test-db                   # тестовая БД на :55432
cd api && npx tsx --test --test-concurrency=1 tests/*.test.ts
```
