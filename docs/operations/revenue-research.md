# Исследование динамики выручки

Инструменты в `scripts/research/` анализируют отдельную выгрузку и не меняют приложение
или данные. Результат относится к указанному снимку, а не к состоянию прода в реальном
времени. Финансовые результаты, адреса, имена сотрудников, заметки и локальные уточнения
остаются вне Git. В Git сохраняются только исходники метода и эта инструкция.

## Входные данные

`revenue-extract.sql` выполняет одну транзакцию `REPEATABLE READ READ ONLY` с явным
списком полей. Учётные данные, полные payload платежей и содержимое фотографий не
выгружаются. Нужны Docker-доступ к **локальному** `site2-db`, `psql` внутри контейнера
и подтверждённая метка исходного снимка в параметре `snapshot_reference`.

Перед выгрузкой проверить локальный Docker context, привязку контейнера к этому
checkout и применённый SHA-256 снимка. Удерживать штатный lock
`backups/from-prod/hourly/.sync.lock`, пока фиксируются метаданные и читается БД:
это предотвращает смену базы почасовой синхронизацией между проверкой и выгрузкой.
Пример чтения уже подтверждённой локальной базы:

```bash
docker exec -i -e PGOPTIONS='-c default_transaction_read_only=on' site2-db \
  psql -XqAt -U apixspb -d apixspb -v ON_ERROR_STOP=1 \
  --set=snapshot_reference="$snapshot_reference" \
  < scripts/research/revenue-extract.sql > "$private_dir/dataset.json"
```

`private_dir` — заранее созданный локальный каталог вне Git с ограниченным доступом.
`snapshot_reference` — время **исходного дампа**, а не время выгрузки JSON. Сохранить
SHA-256 JSON рядом с результатами. Для исследования не требуется копировать фотографии,
запускать парсер или API-тесты.

## Расчёты

Python-инструментам трендов нужны `numpy`, моделям обслуживания — `numpy`, `pandas`
и `scipy`; независимая проверка использует стандартную библиотеку. Версии среды
фиксировать вместе с локальными результатами.

```bash
python3 scripts/research/revenue-decline.py \
  "$private_dir/dataset.json" "$private_dir/results" \
  --overrides "$private_dir/analysis_overrides.json"
OPENBLAS_NUM_THREADS=1 python3 scripts/research/maintenance-revenue.py \
  "$private_dir/dataset.json" "$private_dir/results"
python3 scripts/research/validate-revenue.py \
  "$private_dir/dataset.json" "$private_dir/results"
```

`--overrides` необязателен; его локальный JSON содержит исключённые аппараты и
уточнения владельца. Подтверждённо закрытые локации для моделей обслуживания задаются
повторяемым параметром `--closed-location ID`; реальные ID не встраивать в исходник.
Независимый аудит рассчитан на сентябрь–ноябрь года исходного снимка; `--end` позволяет
явно задать исключительную верхнюю границу. Основной анализ использует последние полные
сутки МСК и сохраняет точные границы окон в метаданных.

## Интерпретация и проверка

- Общая выручка вычисляется по счётчику и снимку цены; безнал является её частью,
  инкассация и прибыль — отдельные показатели.
- Период начинается предыдущим обслуживанием той же установки либо её началом.
  Счётчики разных установок не вычитать друг из друга.
- Деление интервала по календарю предполагает равномерность выручки внутри него.
  Незакрытый хвост неизвестен, его нельзя подставлять как ноль. Для сети проверять
  общий полностью наблюдаемый календарь одинаковой когорты.
- Проверять первые интервалы после изменения начальных показаний, цены, делитель,
  переезды, закрытия, тестовые записи и полноту покрытия.
- Подготовку/закладку игрушек визита сопоставлять с результатом следующего визита.
  Количество заложенных игрушек не является измерением остатка в аппарате.
- Bootstrap и перестановки используют интервалы, а не искусственные дневные строки.
  Правила отбора и описательные интервалы не дают причинной или прогнозной гарантии;
  учитывать множественные сравнения и смешение маршрутов техников.

Проверять синтаксис через `compile()` или с `PYTHONPYCACHEPREFIX` вне репозитория.
Обязательны проверки памяти из `AGENTS.md`; они проверяют навигацию, но не правильность
аналитических выводов. Продуктовые API-тесты для запуска анализа не нужны.
