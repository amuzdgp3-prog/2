# Доступ к 2.apixspb.ru с компьютера разработки

При включённом VPN обычный маршрут может идти через `happ-xray`. Для задач этого
сайта подключайтесь напрямую через физический интерфейс из локальной конфигурации
`/etc/site2-local/sync.env`. На 17.11.2026 проверен Wi‑Fi `wlx0c9160e1d95b`.
При смене адаптера сначала проверьте прямой маршрут и измените значение
`SITE2_PROD_INTERFACE` в этой конфигурации.

```bash
site2_interface=wlx0c9160e1d95b
ip -4 route get 185.147.82.69 oif "$site2_interface"
ssh -B "$site2_interface" -o BatchMode=yes -o StrictHostKeyChecking=yes \
  -o ConnectTimeout=8 root@185.147.82.69 'test -d /opt/sites/2'
curl --interface "$site2_interface" --noproxy '*' \
  --resolve 2.apixspb.ru:443:185.147.82.69 \
  --fail --silent --show-error --max-time 15 https://2.apixspb.ru/api/health
```

Административный SSH используется для выпусков и диагностики. Фоновое задание
читает снимок и фото отдельным ключом `~/.ssh/apixspb_sync` с принудительным
`scripts/sync-guard.sh` на проде. Страж допускает только относительные пути
в `backups/` и `data/photos/` в режиме отправителя rsync. Для диагностики
используйте `rsync -ani` с каталогом назначения. Параметры `--list-only`
и `--timeout` передаются удалённой команде и отклоняются текущим стражем.
Общий лимит времени задаёт локальный `timeout`.

Рабочий ключ OCR хранится на этом ПК в файле заголовка с правами 0600 и на проде
в серверном окружении. Его права ограничены чтением очереди и отправкой
распознанных показаний. Правки обслуживаний доступны через обычную сессию
администратора. Не выводите ключ в команды, логи и Git.

## Почасовые задания

| Где | МСК | Таймер |
|---|---:|---|
| Прод | :00 | `site2-hourly-export.timer` |
| Этот ПК | :05 | `site2-hourly-sync.timer` |
| Этот ПК | :10 | `site2-counter-ocr.timer` |

Статус проверяется через `systemctl list-timers 'site2-*' --all` и
`journalctl -u ИМЯ.service`. Для ручного прогона используйте
`systemctl start ИМЯ.service` на соответствующей машине.

Снимок публикуется в `backups/hourly/site2-latest.dump`. При локальном
восстановлении выключается iVend, проверяется схема и сохраняется предыдущая
база в `apixspb_hourly_previous`. Переключение кратко перезапускает локальный
API. Локальные изменения данных в очередной снимок с прода не попадают.
Фото счётчиков докачиваются без удаления уже скопированных.

OCR выполняется здесь, в `~/.local/share/site2-ocr/venv`. Версии пакетов
зафиксированы в `scripts/counter-photo-ocr-requirements.txt`. Фото обрабатываются
локально. На прод возвращаются два целых числа либо `null`, если счётчики
прочитать не удалось. Для его диагностики на копиях фото запустите
`python scripts/counter-photo-ocr.py --photo ПУТЬ_К_ФОТО` из этого окружения.
