Это карта исходников, триггеров и средств проверки, а не подтверждение исправности

Учётные данные iVend находятся в `parser_settings`, а не только в env
(`api/src/migrations/008_parser_credentials.sql:5–9`). Поэтому копия боевой БД
не становится безопасной для тестов только от очистки переменных окружения.
Локальный `docker-compose.override.yml:4–6` очищает Telegram token/chat и
Resend key, но не исключает живые фото, настройки iVend и планировщики.

## Миграции и разрушительные тесты

В репозитории 28 SQL-миграций: от `001_core.sql` до
`028_counter_photo_checks.sql`. `runMigrations` сортирует имена, пропускает
записанные в `schema_migrations` и применяет каждый следующий файл внутри
транзакции (`api/src/db/migrate.ts:6–35`). `assertMigrationsApplied` проверяет
наличие имён файлов в этой таблице (`:9–14`). Восстановление и отказ на середине
миграции этим чтением кода не подтверждены.

`api/tests/helpers.ts:25–27` безусловно выполняет
`DROP SCHEMA public CASCADE; CREATE SCHEMA public;`. Значения `DATABASE_URL`
и `PHOTO_DIR` задаются через `??=` (`:4–7`), поэтому унаследованные значения
не заменяются. Требуется доказать изоляцию до запуска тестов. Имя БД или порт
55432 сами по себе этого не доказывают.

## Изолированный контур первого этапа

Воспроизводимый запуск описан в `scripts/review-isolated-api-tests.py`.
Он использует локальный Docker Unix socket и зафиксированные на время запуска
локальные image ID, создаёт новую internal network и PostgreSQL с новым tmpfs,
без опубликованных портов. До SQL-тестов проверяются mounts, сеть,
`current_database`, `current_user`, `pg_control_system().system_identifier`
и отсутствие пользовательских таблиц.

Тестовый runtime использует сетевое пространство только созданного PostgreSQL,
read-only root и узкий список read-only mounts исходников/зависимостей.
Папка фото находится в tmpfs `/tmp`. Окружение процесса очищается через
`env -i`; пароли/JWT синтетические, внешние API направлены на loopback.
Фотообработка использует локальный `ffmpeg` (`api/src/lib/photos.ts:24–56`).
API-тесты вызывают `buildServer()` через helper, не обычный entrypoint.

Runner сохраняет хеши исходников, image ID, доказательства изоляции, состояние
runtime, результаты очистки и лог в уникальный каталог `/tmp`. Удаляются
только ID контейнеров/сети, полученные при этом запуске. Команды:

```bash
python3 scripts/review-isolated-api-tests.py --preflight-only
python3 scripts/review-isolated-api-tests.py
```

Статус реального прогона и его результаты должны браться из итогового отчёта
этапа и конкретного `isolation.json`, а не из этой статической карты.
Preflight доказывает предпосылки запуска, но не прохождение API-тестов.
